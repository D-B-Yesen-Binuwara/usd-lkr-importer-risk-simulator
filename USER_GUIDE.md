# User guide

## What is available

This repository provides data preparation, a 2019–2024 calendar-time GBM fit, exact GBM rate simulation and a bounded two-state Markov volatility model. It does not yet provide importer-risk metrics or an interactive web demo.

## Prepare the data

1. Create and activate a Python environment.
2. Install dependencies with python -m pip install -r requirements.txt.
3. From the repository root, run python -m src.prepare_data.
4. Check data/processed/data_quality_report.json for the source hash, row counts, exclusions and date-gap summary.

The run reads data/raw/CBSL_USD_TT_Selling.csv. It writes cleaned quotes, adjacent-observation log returns, calibration/evaluation files and a quality report under data/processed/. It refreshes figures/usd_lkr_selling_rate.png. The raw CSV is not modified.

## Inspect the outputs

| File | Contents |
|---|---|
| data/processed/cleaned_usd_lkr.csv | Canonical date, USD TT selling rate and source label. |
| data/processed/daily_log_returns.csv | Adjacent observed quote pairs, log return and calendar gap in days. |
| data/processed/calibration_quotes_2019_2024.csv | Quotes in the initial calibration window. |
| data/processed/calibration_returns_2019_2024.csv | Returns with both quote dates inside the calibration window. |
| data/processed/evaluation_quotes_2025_2026.csv | Available quotes in the evaluation window. |
| data/processed/evaluation_returns_2025_2026.csv | Returns whose current quote date falls in the evaluation window. |
| data/processed/data_quality_report.json | Audit and summary values generated by the pipeline. |
| data/processed/gbm_calibration_2019_2024.json | Annual GBM coefficients, training interval, input hashes and model limitations. |
| data/processed/markov_calibration_2019_2024.json | Training-only stable/volatile threshold, counts, transition matrix, conditional residual RMS and input hashes. |

The first evaluation return can use the final 2024 observation as its previous quote. Calendar gaps are retained; weekends, holidays and missing dates are not filled.

## Fit the GBM and sample rates

Run `python -m src.calibration` from the repository root after preparing the data. It fits only returns with both dates in 2019–2024, validates the CBSL TT selling-rate source and saves `data/processed/gbm_calibration_2019_2024.json`. The variance estimate uses the Gaussian maximum-likelihood divisor `n`; each gap is measured in calendar days divided by 365.

For a reproducible illustrative set of **exchange-rate** outcomes from the last 2024 quote:

```python
from pathlib import Path
from src.calibration import baseline_calibration_report
from src.gbm import simulate_terminal_rates

c = baseline_calibration_report(Path.cwd())["calibration"]
rates = simulate_terminal_rates(
    c["last_rate_lkr_per_usd"], c["alpha_per_year"], c["sigma_per_sqrt_year"],
    horizon_days=90, n_paths=1000, seed=42,
)
print(rates[:5])
```

This draws terminal rates over exactly `90/365` model years. Do not interpret them as a validated forecast or importer VaR/ES; those calculations and checks are later work.

## Fit the bounded Markov extension

Run `python -m src.markov` after the GBM calibration. The same 2019–2024 returns and annual GBM log drift produce the stable/volatile threshold and two-row transition matrix. `stable` means the absolute gap-standardized residual is at or below the training 70th percentile; `volatile` means above it. The report records 1,011 and 433 training returns in those states. Both rows have observed outgoing transitions and sum to one.

For an illustrative rate-path draw from the last 2024 quote:

```python
import pandas as pd
from src.markov import fit_two_state_markov, simulate_markov_paths, weekday_quote_offsets

model = fit_two_state_markov(pd.read_csv("data/processed/calibration_returns_2019_2024.csv"))
quotes = weekday_quote_offsets(model.last_quote_date, 90)
paths = simulate_markov_paths(
    model.last_rate_lkr_per_usd, model.alpha_per_year,
    model.state_volatilities_per_sqrt_year, model.transition_probabilities,
    model.last_state, horizon_days=90, quote_day_offsets=quotes,
    n_paths=1000, seed=42,
)
print(paths.rates[:5, -1])
```

The helper assumes Monday–Friday quotations, including any weekday that is actually a holiday; supply verified quote-day offsets when available. The first future quote samples a **new** state before its rate increment. If the invoice is due after the last assumed quote, the final calendar gap uses the current volatility without another state transition. This models rates only, not invoice costs or VaR/ES.

Install the optional notebook interface with python -m pip install notebook if it is not already available, then run jupyter notebook notebook/usd-lkr-importer-risk-simulator.ipynb from the repository root.

## Run validation checks

Run `python -m pytest -q` from the repository root. The local Windows virtual environment rerun on 2026-11-23 passed 44 tests in 5.83s. These include the GBM checks plus independent Markov counts, probability rows, linked quote/date pairs, holdout isolation, state ordering, gap/remainder behavior, seed replay and long-run synthetic transition frequencies. A Linux/Colab run remains to be done. These checks do not establish upstream CSV authenticity or real-world predictive suitability.

## Current limitations

- The downloader identified the official CBSL daily buy/sell page, but the exact export, download date and reuse terms for the local CSV remain unresolved.
- The fitted primary GBM uses each actual calendar gap divided by 365 years; it assumes variance accumulates over non-quotation days. A separate 252-quote-session comparison remains to be run with a stated future quotation schedule; see THEORY.md.
- The 2025–2026 evaluation data is partial through 2026-11-19.
- Constant-GBM parameters and the volatile-state RMS reflect the large 2022 movements and may be unstable. The Markov labels are a heuristic, not independently observed economic regimes. Importer payment metrics, model sensitivity experiments and the browser demo remain future work.
