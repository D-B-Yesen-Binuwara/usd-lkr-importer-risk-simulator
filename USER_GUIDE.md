# User guide

## What is available

This repository provides data preparation, a 2019–2024 calendar-time GBM fit, a bounded two-state Markov model, and reproducible hypothetical importer payment-risk calculations. The interactive web demo remains to be built.

## Prepare the data

1. Create and activate a Python environment.
2. Install dependencies with python -m pip install -r requirements.txt.
3. From the repository root, run python -m src.prepare_data.
4. Check data/processed/data_quality_report.json for the source hash, row counts, exclusions and date-gap summary.

The run reads data/raw/CBSL_USD_TT_Selling.csv. It writes cleaned quotes, adjacent-observation log returns, calibration/evaluation files and a quality report under data/processed/. It refreshes figures/usd_lkr_selling_rate.png. The raw CSV is not modified.

## Inspect the outputs

| File | Contents |

| data/processed/daily_log_returns.csv | Adjacent observed quote pairs, log return and calendar gap in days. |
| data/processed/calibration_quotes_2019_2024.csv | Quotes in the initial calibration window. |
| data/processed/calibration_returns_2019_2024.csv | Returns with both quote dates inside the calibration window. |

| data/processed/gbm_calibration_2019_2024.json | Annual GBM coefficients, training interval, input hashes and model limitations. |
| data/processed/markov_calibration_2019_2024.json | Training-only stable/volatile threshold, counts, transition matrix, conditional residual RMS and input hashes. |

| data/processed/stage7_comparisons.json | Frozen-input GBM calibration, volatility and clock comparisons; per-seed uncertainty and replicated mean-error convergence. |

The first evaluation return can use the final 2024 observation as its previous quote. Calendar gaps are retained; weekends, holidays and missing dates are not filled.

## Fit the GBM and sample rates

Run `python -m src.calibration` from the repository root after preparing the data. It fits only returns with both dates in 2019–2024, validates the CBSL TT selling-rate source and saves `data/processed/gbm_calibration_2019_2024.json`. The variance estimate uses the Gaussian maximum-likelihood divisor `n`; each gap is measured in calendar days divided by 365.

For a reproducible illustrative set of **exchange-rate** outcomes from the last 2024 quote:

```python
from pathlib import Path
from src.calibration import baseline_calibration_report
from src.gbm import simulate_terminal_rates

c = baseline_calibration_report(Path.cwd())["calibration"]
rates = simulate_terminal_rates(
    c["last_rate_lkr_per_usd"], c["alpha_per_year"], c["sigma_per_sqrt_year"],
    horizon_days=90, n_paths=1000, seed=42,
)
print(rates[:5])
```

This draws terminal rates over exactly `90/365` model years. It is a rate-only example; run the invoice scenario below for payment metrics.

## Fit the bounded Markov extension

Run `python -m src.markov` after the GBM calibration. The same 2019–2024 returns and annual GBM log drift produce the stable/volatile threshold and two-row transition matrix. `stable` means the absolute gap-standardized residual is at or below the training 70th percentile; `volatile` means above it. The report records 1,011 and 433 training returns in those states. Both rows have observed outgoing transitions and sum to one.

For an illustrative rate-path draw from the last 2024 quote:

```python
import pandas as pd
from src.markov import fit_two_state_markov, simulate_markov_paths, weekday_quote_offsets

model = fit_two_state_markov(pd.read_csv("data/processed/calibration_returns_2019_2024.csv"))
quotes = weekday_quote_offsets(model.last_quote_date, 90)
paths = simulate_markov_paths(
    model.last_rate_lkr_per_usd, model.alpha_per_year,
    model.state_volatilities_per_sqrt_year, model.transition_probabilities,
    model.last_state, horizon_days=90, quote_day_offsets=quotes,
    n_paths=1000, seed=42,
)
print(paths.rates[:5, -1])
```

The helper assumes Monday–Friday quotations, including any weekday that is actually a holiday; supply verified quote-day offsets when available. The first future quote samples a **new** state before its rate increment. If the invoice is due after the last assumed quote, the final calendar gap uses the current volatility without another state transition.

## Run the hypothetical importer invoice

Run `python -m src.run_risk` from the repository root. Its documented default is USD 100,000 payable on 2025-03-31, 90 calendar days after the last 2024 training quote. The reference cost is LKR 29,701,620; the hypothetical budget is 5% higher at LKR 31,186,701. Both models use seeds 42–49 and 10,000 paths per seed. The Markov run uses 64 assumed Monday–Friday quote dates. The JSON report stores the schedule and every seed's metrics.

`src/risk.py` computes future cost `Q*S_T`, signed extra cost `Q*(S_T-S_0)`, expected and median cost, 5th/95th cost percentiles, strict budget exceedance, and the upper 95% VaR/ES of **extra cost**. A negative extra cost is a saving, not reset to zero. VaR uses the empirical left quantile; ES averages exactly the worst 5% of sample mass with fractional boundary weighting. The pooled mean-cost 95% Monte Carlo interval uses sample SD divided by the square root of path count. The report also shows between-run SD and range for VaR/ES; those spreads are not confidence intervals.

The baseline report is a retrospective hypothetical scenario anchored at end-2024, not a real invoice or a live 2026 forecast. Monte Carlo precision does not include parameter, 2022-regime or source-data uncertainty.

## Run verification and sensitivity comparisons

Run `python -m src.experiments`. The command fits the predeclared 2019–2021, 2022–2024 and full 2019–2024 windows, plus a separately labelled 2022-excluded fit using two disjoint blocks of real adjacent returns. It does not create a return bridging 2021 and 2023 or use 2025–2026 to fit parameters. It also tests 0.75× and 1.5× baseline volatility with log drift held fixed, and a separate 252-equal-quote-session approximation. That alternative uses the sample SD of quote returns, 252 sessions/year and 64 assumed future weekday quotes, so its horizon is `64/252` rather than `90/365` years.

The cases reuse the Stage 6 USD 100,000 invoice, reference quote, 90-day due date, LKR budget, eight seeds and 10,000 paths per seed. GBM cases reuse each seed's normal draws to reduce comparison noise. The JSON contains pooled cost/VaR/ES metrics, between-seed SD/min/max and parameter values. `figures/stage7_scenario_comparison.png` shows VaR/ES with **between-seed SD**, not confidence-limit, error bars. `figures/stage7_gbm_convergence.png` shows replicated mean-cost RMSE at 500, 2,000, 8,000 and 32,000 paths across 32 seeds against analytical GBM MC standard error. The observed log–log RMSE slope is −0.495; individual run errors need not decrease monotonically.

The comparisons describe calibration, clock and assumed-volatility sensitivity conditional on the models. They are not a selection of the best forecast window or an out-of-sample validation.

## Run validation checks

Run `python -m pytest -q` from the repository root. The local Windows virtual environment rerun on 2026-11-24 passed 64 tests in 5.53s. Stage 7 adds five checks for training-only window definitions, session annualization, analytical GBM moment/quantile agreement, replicated mean-error scaling and saved-comparison reproducibility. A Linux/Colab run remains to be done. These checks do not establish upstream CSV authenticity or real-world predictive suitability.

## Current limitations

- The downloader identified the official CBSL daily buy/sell page, but the exact export, download date and reuse terms for the local CSV remain unresolved.
- The fitted primary GBM uses each actual calendar gap divided by 365 years; it assumes variance accumulates over non-quotation days. The executed 252-quote-session comparison uses an assumed future weekday schedule and does not establish which clock predicts better; see THEORY.md.
- The 2025–2026 evaluation data is partial through 2026-11-19.
- Constant-GBM parameters and the volatile-state RMS reflect the large 2022 movements and may be unstable. The Markov labels are a heuristic, not independently observed economic regimes. The executed sensitivity experiments quantify that dependence but do not validate a forecast. The browser demo remains future work; Monte Carlo intervals are conditional on fitted models.
